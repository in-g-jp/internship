## このコースで学ぶこと

コードの変更履歴を管理する Git の基本を学びます。
次のステップで実際に Git を使うので、ここで概念を理解しておきましょう。

| 概念       | 説明                           |
| ---------- | ------------------------------ |
| リポジトリ | コードの変更履歴を管理する場所 |
| コミット   | 変更を記録するスナップショット |
| ブランチ   | 独立した作業ラインを作る仕組み |
| マージ     | ブランチを統合する操作         |

## コミットメッセージ

コミットメッセージは「どんな変更をしたか」を記録するものです。
あとから見返したときに変更内容が伝わるように書くのがポイントです。

### 良いコミットメッセージの書き方

```
ユーザー登録フォームにバリデーションを追加
```

- **何をしたかが一目でわかる**短い文で書く
- 「修正」「変更」だけでは何をしたかわからないので具体的に書く
- 日本語・英語どちらでもよいが、チームで統一する

コミットメッセージの先頭には変更の種類を表す接頭辞をつけると、履歴が読みやすくなります。

参考：[コミットメッセージの接頭辞について](https://qiita.com/muranakar/items/20a7927ffa63a5ca226a)

### 悪い例

```
修正        # 何を修正したかわからない
update      # 何をアップデートしたかわからない
あああ       # 作業中のメモをそのままコミットしている
```

### プロジェクトごとのルール

チームやプロジェクトによってコミットメッセージのフォーマットが決まっていることがあります。
このインターンでは Paiza の問題を解くリポジトリで **「問題番号: 解答にかかった時間」** というフォーマットを使います。

```
C001: 5分20秒
```

## ブランチ

ブランチは「作業用のコピー」のようなものです。
`main` ブランチを直接編集せず、作業用のブランチを作って変更を加えるのが基本的な使い方です。

### なぜブランチを使うのか

`main` ブランチは動いているコードの基盤です。
直接 `main` で作業すると、途中の壊れた状態が全員に影響してしまいます。
ブランチを切ることで、完成するまで安全に作業できます。

```
main ────────────────────────────── ← 常に動く状態を保つ
         └── feature/login ──┘      ← ここで作業してマージ
```

### ブランチの命名

わかりやすい名前をつけることが重要です。このインターンでは以下の形式を使います。

| 作業内容           | ブランチ名の例      |
| ------------------ | ------------------- |
| Paiza の問題を解く | `feature/C001`      |
| 新機能の追加       | `feature/add-login` |
| バグ修正           | `fix/login-error`   |
